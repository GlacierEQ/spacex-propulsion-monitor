# AKOS / APEX Bridge

Operating method: **GlacierEQ/AKOS APEX LOGIC**

This repository participates in the APEX Capability Evolution Graph.

## Active machine surfaces

- `machine/capability-planes.json` — implementation, evidence, current selections, challengers, donors, projection, target frontier, and lineage.
- `machine/target-contract.json` — thin routing contract into the richer capability graph.
- `machine/excellence-state.json` — current proof and evolution state.
- `machine/excellence-scores.json` — objective-relative multidimensional fitness, never permanent repository rank.

## Execution rules

1. Inspect current implementation and evidence before changing anything.
2. Select per capability, not per repository.
3. Every selected route remains challengeable.
4. Preserve unique donor mechanisms and verified checkpoints before replacement or retirement.
5. Projection may qualify claims but may not erase richer implementation, intent, target, donor, or lineage state.
6. Prefer composition when multiple implementations contribute unique value.
7. Verification is a checkpoint for further engineering, not a ceiling.
8. Continue through discovery, comparison, innovation, implementation, adversarial verification, operation, and evolution.

APEX is the method for dynamic evidence-backed improvement. It is not a permanent throne for a repository, branch, snapshot, or process artifact.
